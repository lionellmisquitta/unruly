# FOLDER1 interaction baseline

User authorized the next standalone folders checkpoint. Existing Layers panel is the hierarchy explorer alongside the drawing canvas. No new app/surface. Select layers using existing checkbox or Ctrl/Cmd-click, Group selected layers wraps same-parent leaves and makes non-adjacent selections contiguous at their topmost selected position, preserving internal paint order. Undo reverses order and membership. Folder rows expand/collapse (view state), select descendant layers for lasso, offer rename, visibility, lock, Transform contents, move-to-folder/top-level, Up/Down block move, and Ungroup. Group opacity/effects are deferred; folders are pass-through. No destructive folder-delete action. Ungroup refuses locked descendants and keeps their original visibility/lock values. Empty folders remain accessible for reentry.

Inherited hidden/locked state blocks paint/smudge/erase/paste/lasso/transform without mutating child state. Group transforms use existing shared pivot, Apply/Cancel, pinch/twist and single command Undo. Children remain independent vectors/rasters. Layer ordering is constrained to siblings; hierarchy boards use explicit move destinations and Up/Down controls rather than ambiguous drag reparenting. Flat boards retain existing touch drag/swipe controls. Folder buttons stay at least44px; nesting bounded8 ancestors and16 folders, drawing cap32 unchanged.

Evidence SUFFICIENT for grouping/nesting, tablet controls and transform from user workflow and prior accepted layer controls. Pass-through composition CONDITIONAL on this checkpoint only; change trigger is later masks/group effects. Physical tablet latency/RAM NOT_VERIFIED; no claims beyond synthetic Chromium and pixel-reference oracle. Save compatibility is v5 only when grouping occurs; old v1-v4 readers remain and old builds cannot open v5. Export-backup note is visible.
