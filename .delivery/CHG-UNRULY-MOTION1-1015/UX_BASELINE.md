# UX baseline — MOTION1
UXD-M1: Existing spatial canvas plus compact inspector; no separate animation lab. A generic wizard/modal blocks seeing the path and is rejected. Reuse the current dark inspector/system-font/touch-target visual system; neon amber path is a functional authoring overlay, hidden during presentation.

UXD-M2: Actions→Motion Trace; selection→Trace selection; folder Actions→Motion Trace. Opening captures current object/pixel target; folder entry captures group. No selection still permits saved playback/camera authoring. Draft name,seconds,path endpoint inputs and camera centre/zoom; draw path with pen/mouse on canvas, binary region selection reused exactly. Path drag offsets from pen-down, anchored visually at target centre. Numeric endpoints offer keyboard equivalent.

UXD-M3: Save cue affects metadata only, one Undo. Reorder/delete cues explicitly. Presentation compiles all selected cues against a captured immutable board. Manual Next is default; Timed advances after each duration. Pause/Resume explicit; visibility/blur pauses and never auto-resumes. Stop resets board/view; Close additionally discards unsaved draft. Commit shown separately during preview/presentation, writes final geometry at current position once, restores original authoring view; camera-only commit creates no artwork/history change.

UXD-M4: Missing/hidden/locked/source-changed target blocks playback atomically; user can delete cue or replace its target using current selection after closing/reopening. Malformed/oversized native files rejected by model before import/storage. No silent dropped target. Pending save/failure and existing stale-revision conflicts remain owned by storage. Playback never changes persisted revision. Editing elsewhere/board transitions blocked while UI open.

UXD-M5: Single inspector view and canvas; mobile inspector scrolls and collapses during path drawing/presentation.44px touch targets,visible focus,labeled fields/status,error region; Escape restores original, Tab stays within inspector when authoring and playback controls when presenting. No unsolicited autoplay; explicit timed selection.

Evidence sufficient: original scope and current source establish the reversible interaction. Conditional implementation choices: bounded cue/path budgets,relative paths and small native v14metadata extension. Change trigger: user asks for rotation/scaling/motion-video coupling or cross-board cue exchange. Not included or claimed. UX/visual previews surfaced in commentary; existing user authorization to build lets reversible implementation proceed without ceremonial reapproval.
