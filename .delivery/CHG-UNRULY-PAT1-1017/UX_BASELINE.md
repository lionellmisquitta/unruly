# PAT1 locked UX / existing UI direction
Small existing-app workflow extension, evaluated in same session with UX Architect and UI Design Director methods; no independent review claimed.

Actions → Deform image / pattern. Exactly one selected raster on active editable visible layer; otherwise clear selection instruction. Imports already select their raster. Region selection cannot silently deform whole layer. A dialog shows local transparent/checkered preview with four labelled draggable corner handles and X/Y percent controls (0–100). Corners clockwise TL/TR/BR/BL. All source pixels map into a convex quadrilateral inside the existing rectangle, >=1% area; invalid geometry explains error and disables Apply. Numbers keyboard-accessible; pointer capture; pointercancel restores pre-drag draft. Input changes preview on release/change, not full-source resampling on every pointermove. Source retained for all draft revisions. Existing canvas behind modal previews composed result for context; transparent preview excludes paper. Reset restores rectangle; Cancel/Escape restores board exactly; Apply one Undo step. Opening identity/Reset Apply does not add history if pixels unchanged. Draft ties exact board object/layer/stroke; stale commit refused.

Visual: reuse warm neutral dialog, typography, existing primary/secondary buttons, focus rings and semantic tokens; no redesign. Preview maximum320px, numeric pairs in2columns, dialog scrollable within viewport, >=44px corner targets, touch-action none only preview. Phone390px and desktop1024px screenshot inspection; keyboard, pointercancel and errors covered. Limits and baked-pixel semantics explicit in dialog.
