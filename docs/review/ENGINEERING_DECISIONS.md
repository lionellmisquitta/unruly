# Engineering decisions for independent readiness review

3 October 2026. These are bounded architect recommendations derived from the saved requirements. Confirmed GDEC records retain their meaning. The proposals below are not user confirmations, locked UX, runtime selection or production authorization. All executable implementation checkpoints remain blocked until independent readiness passes.

| ID | Recommendation and consequence | Verification / dependency boundary |
| --- | --- | --- |
| EDR-001 | Shared document/geometry/brush policy with thin native input, file, credential, rendering and packaging adapters. Qt 6 remains a candidate. Keep the P0 QPainter loop quarantined. Local drawing has no hosted backend or app account. | P0a–P0c, portable Windows folder and Xiaomi APK/device evidence before G10 lock. |
| EDR-002 | Stable opaque IDs for boards, layers, objects, tiles, artboards, assets and cues. Document coordinates are independent of viewport/DPI. Save committed revisions only; background work reads immutable snapshots and can publish only against its source revision. | C02/C03 history/state property tests; C09M replay restoration; C11 lineage/conflict tests. |
| EDR-003 | Proposed board-v1 container: ZIP64 with versioned JSON manifest, JSON vector/object/cue records, referenced original assets and lossless PNG raster tiles. Use 256×256 tiles initially and explicit content checksums. Major-version mismatch rejects without altering input; migrations operate on a retained copy. No arbitrary executable archive entries. | Choose format only at G08 review; bound entries, decoded sizes, paths and compression ratio before C02. Validate exact serialization/recovery fixtures. ZIP is a format proposal, not an implemented loader. |
| EDR-004 | Saving stages a sibling temporary revision, flushes and validates it, then uses the platform's supported replacement primitive; retain the prior validated revision. Label durable/saved only after the actual platform durability contract. Failed/cancelled operations never enter history. | Fault injection after each write/flush/replace stage on Windows and Android; Android storage permissions and external-storage semantics need separate proof. |
| EDR-005 | Working raster proposal: sRGB RGBA8, premultiplied alpha for composition, explicit straight-alpha conversion at PNG exchange boundaries. Begin with normal/multiply/screen/overlay/add blend reference fixtures; expand only with defined math. Colour management and watercolour fidelity remain review boundaries. | G10 colour/alpha reference tolerances and supported subset must be fixed before C04/C05. Do not claim wide-gamut or another app's fidelity. |
| EDR-006 | Every fill/blur/export has a finite artboard/selected rectangle and tiled cancellation. Proposed initial import guardrails: 16,384 pixels per axis, 256 MiB decoded bytes per item, 4 MiB manifest and 65,536 archive entries. Check integer products before allocation; these are reviewable maxima, not minimum device-memory assumptions. | G05/G08/G11 approve or reduce after target-memory evidence. C07/C09 negative tests cover each bound and aggregate memory budgets; no infinite flood. |
| EDR-007 | One committed document transaction per undoable operation; live stroke previews and presentation camera are ephemeral. Store raw pen samples separately from filtered output in measurement fixtures. Gesture state machines explicitly arbitrate idle/active/commit/cancel and pointer IDs. | Native P0b identity/eraser/palm/display/lifecycle tests and locked gesture delays before C03/C06. P0a has no gesture implementation. |
| EDR-008 | Proposed performance targets: at 60 Hz, p95 visible frame processing ≤16.7 ms; at higher refresh, declare the effective frame budget. Proposed measured input-to-visible p95 ≤50 ms with instrumentation and dropped-sample accounting. Use a 30-minute scripted drawing workload plus concurrent save/fill/export. | P0c measures actual targets; Gatekeeper approves budgets and workload sizes at G05. Startup/synthetic events and human impressions do not prove these numbers. |
| EDR-009 | Record timelapse from a versioned operation stream with referenced raster assets, separate from undo compaction. Proposed default captures chronological actions including undo and explicit finite framing, with user-controlled recording/retention. Commit-to-board Motion Trace is recorded once; presentation-only playback does not mutate board history. | Framing, undo portrayal, storage cap and retention are material unresolved choices before C10. No automatic deletion or upload; replay and interrupted-export fixtures must bind these choices. |
| EDR-010 | Proposed exchange route: app-native editable master plus bounded layered PSD interoperability, with documented rasterization and losses. Native .clip/.procreate writing is a separate feasibility task. | User/review acceptance of exchange route and real external-app roundtrip fixtures before C10; unsupported metadata is disclosed. |
| EDR-011 | Local state remains authoritative offline. Drive adapter preserves both conflicting revision lineages and lets the user choose continuation. AI adapter transmits explicitly selected content only after review; received output is previewed before insertion. Keys/tokens remain in native credential stores outside boards and logs. | Drive scope/OAuth consent, providers/capabilities and cost caps remain material choices before C11/C12. Require versioned sanitized samples and zero-live-egress simulation before implementation. No real private boards in QA. |
| EDR-012 | Record Qt/compiler/package pins per environment and verify downloads against official index checksums. Native hardware runs use host kits. Propose Compose for integration simulators and deterministic engine regression, without inventing a server/database. Native hardware evidence remains outside containers. | Gatekeeper must reconcile the installed skill's Docker-first rule for C01; no human Docker exception is inferred. Clean-clone build, signed release dependencies, vulnerabilities and Qt redistribution obligations remain unverified. |
| EDR-013 | Project license remains undecided. Prepare an MIT project-license recommendation for review; evaluate dynamically linked Qt's actual module licenses/notices and redistribution obligations before binary distribution. Current source/preparation branch push is not a binary release. | G11/G13 dependency/license review and explicit project-license decision. Do not insert a license or claim compatibility on the user's behalf. |
| EDR-014 | Controller stops on unexpected repo routing, unbound identities, timeout, malformed result, missing evidence or failure after merge. Builder owns source, independent QA owns fixtures, independent Gatekeeper owns readiness. Maximum three application repair/retest cycles; P0a has used one. | C01 locks unattended time/token/cost ceilings, isolation/CI and rollback. Current bounded Claude calls: tools disabled, isolated packets, 180-second timeout and $3 reported-usage ceiling per call. No subscription purchase or recursive agent loop. |

For each EDR, owner is the delivery architect; acceptance is independent Gatekeeper review plus a human decision where the material choices above require it. No recommendation silently changes GDEC-001 through GDEC-020. Proposed numbers and defaults must be linked to tests before adoption; record any accepted change as a new decision delta.

The complete draft slice contracts are in `CHECKPOINT_CONTRACTS.json`: P0a/P0b/P0c and C01–C13 including C09M. Each includes criteria, deterministic fixtures, dependencies, execution blockers, permitted scope, prohibited behavior, impacted regression and rollback. They do not authorize production scaffolding.
