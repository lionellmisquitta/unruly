## Required targeted contract before WEB-W1 code

1. **Lock actual control behavior.** Use in-app controls, avoiding native colour dialogs as the only path. Specify slider/numeric size1–40, brush opacity0–100%, bounded colour input/HSL/palette behavior, live sample, labelled values, pointer/touch targets and keyboard behavior. State whether opacity0 is valid invisible ink and how preview explains it. Existing strokes are immutable to control changes. Include360px/tablet layout, open/close/cancel drawer behavior and draw-after-control focus recovery. Automated tests must assert changed pixels/stroke metadata, not only changed input values.
2. **Choose one exact layered schema and history contract.** Define proposed version2 Board/Layer/Stroke keys, unique IDs/order, active selection, per-stroke brush/opacity, per-layer opacity/visibility/lock, and paper metadata. Suggested bounded scope: max32 vector layers, existing total2000 strokes/100000 points/8MiB limits unchanged; validate duplicate/missing layer references. Layer name/order/show-hide/lock/delete and active-layer changes have explicit transactional undo semantics; deletion is undoable and cannot silently discard the last recoverable state. Locked or hidden active layer cannot accept ink/erase. Define post-delete active layer and the last-layer rule before code.
3. **Pin composition math.** Brush opacity applies to a complete stroke; layer opacity applies after rendering the complete layer to an isolated intermediate surface. Alpha combines without independently darkening overlapping stroke segments. Only normal source-over blend in WEB-W1. Define pressure-width/zero-pressure semantics and transparent/hidden pixels for eraser hit tests. Use fixed deterministic reference pixels with tolerance and finite DPR/backing-store limits. A title or layer control alone is not composition acceptance.
4. **Make paper repeatable.** Plain/dotted/grid/ruled/original procedural-texture options, colour/spacing/seed bounds, document-coordinate anchoring and zoom behavior need explicit metadata/math. Save/reopen reproduces the paper. Define whether JSON export includes paper and whether later artwork export includes it. No external texture parsing in WEB-W1.
5. **Migration must preserve older app compatibility.** Recommend a distinct version2 storage namespace: read/validate v1, copy its strokes to a new default vector layer, verify new record, and commit it there without modifying/deleting v1 original or its last-good snapshot. Bind original board/revision lineage. Migration cannot report success before durable completion; corrupt/quota/cancel leaves original unchanged. The previous v1 app must never see or overwrite v2 data. A rolled-back v1 app sees original v1 state, not post-migration edits; disclose and preserve v2 exports/snapshots. Resolve mixed-tab v1/v2 editing explicitly as separate revisions/forks rather than silently overwriting. Keep existing conflict safeguards in each namespace.
6. **Resolve import dependency without scope creep.** The proposal requires import before promoting a migration-dependent preview, but an import parser is a separate uncontracted capability. Either supply a bounded validated import contract/tests, or explicitly replace that prerequisite with retained v1 namespace + validated non-destructive copy + preserved v2 recovery/export and separate restore support before user-data migration release. No implication that JSON export already means import exists. Do not silently remove a previously promised recovery mechanism.
7. **Bind tests, identities and deployment rollback.** Exact allowed file manifest, tested baseline/deploy identity, independent QA handoff and deterministic fixtures must be supplied. Required tests: real IndexedDB v1→v2 valid/corrupt/quota/conflict paths; alpha/reference pixels; control→new stroke→save/reopen; layer visibility/order/opacity/lock/delete/undo; paper navigation/reopen; offline pending-worker safe upgrade. Store namespaces and original snapshots must survive rollback. Old/new application incompatibility cannot be patched by silently clearing site data.
8. **Record a measurable bounded workload and run cap.** Keep representative layered point count/canvas dimensions/DPR known; measure pointer-to-frame, long-session memory/render activity and responsiveness while save runs. Synthetic timings do not prove buttery device feel. Set one task/call/CI ceiling and explicit permitted repair cycles before code; zero paid CLI/API calls remains default. Existing exhausted repairs are never erased. Stop after actual diagnosed instability, not another unrestricted implementation/review loop.
