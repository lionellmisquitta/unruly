# P01 — Retained live-ink rendering, preview v0.3.0

Status: designed; independent readiness pending. User authorized design/build/test/push on 6 October 2026. Existing MIT/browser-first/no-login UX remains locked. Prototype only; main and production authorization remain false.

## Objective and dependency
Improve the measured full-board replay bottleneck before adding expensive painting features. Baseline live source e30e861745c48c5029c7f9f0d23a974ae8190c54, metadata parent 86a4c29fe67d5a984207f9bdb940c92ffffc5fde. Existing desktop 8-layer/10,000-point full-replay p95 55.7ms is historical context, not the paired benchmark for this change.

## Locked architecture and UX
Same URL, controls, four brushes, pressure and pen-first interaction. Cache completed lower layers plus paper and the completed active layer during live strokes on the topmost visible nonzero-opacity layer. Compose preview into the active layer BEFORE layer opacity, preserving overlap/order/alpha. If any visible nonzero upper layer exists, use unchanged full-replay semantics; middle-layer acceleration is deferred. Full replay remains the correctness reference and automatic fallback.

Five fixed canvases: visible main, reusable layer and stroke scratch, cached lower composite, cached active layer. No per-layer allocation. Cap backing dimensions at4096 and total nominal RGBA backing bytes at80MiB; scale backing DPR down as necessary. This is backing-pixel allocation accounting, not a claim about complete browser/GPU memory. Existing DPR<=2 cap remains. All renderer paths/reference use the same dimensions. Brush-sample uses existing scratch; explicitly invalidates cache. Cache key includes board object identity, revision, active layer, view coordinates/scale, backing dimensions/DPR. Board is immutable during live stroke; application commands create new board identities. No preview cache trusted after full render, cancellation, commit, history/board transition, sample, resize or view change. Mutating a board in place requires explicit full render/invalidate; direct data mutation is not the app contract.

## Acceptance and failure contracts
P01-A1: cached/reference output byte-identical at equal dimensions across all four brushes, pressure/null/zero, stroke and layer opacity including0, crossings/overlap, opaque/translucent active layer, papers and view transforms. Middle-layer fallback is byte-identical; no wider pixel tolerance authorized.
P01-A2: first live preview may replay completed content; subsequent frames on unchanged board/view replay ZERO completed strokes. Changed preview length/pressure must appear correctly. Error invalidates cache and leaves existing Render limit status/recovery.
P01-A3: paired deterministic 8layers/10000completed points, 1440x950 CSS DPR1, active top layer, four brush mix, live ink preview128points, warmup then20 samples: cached p95 <=50% reference p95 and <=16.7ms target. This is renderer CPU duration only, not physical pen-to-display latency. If target fails record failure and stop/replan; do not alter fixture/threshold for green.
P01-A4: five constant surfaces, dimensions<=4096, sum(width*height*4)<=80MiB at desktop/tablet DPR1/2/3 and resize. No surfaces per stroke/layer/board.
P01-A5: inherited24 model and21 browser journeys pass: draw/save/reload, undo/redo, all erasers, selection, copy/move/delete, migration, quota/conflict/recovery, offline/update safety, mobile controls. Existing3-surface assertions may be updated by QA ONLY to the newly locked5-surface budget; no weakening unrelated assertions.
P01-A7: live penmove schedules rendering without full-board selection validation/toolbar refresh; pressure reporting and coalesced sample collection remain.
