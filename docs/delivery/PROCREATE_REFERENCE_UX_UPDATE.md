## Changes to the three-checkpoint plan

U1: replace wide permanent inspector/labelled toolbars with reference-style icon toolbar and overlay layers; compact thumbnail rows, add-above-active, opacity/blends via selected-row blend control, hold-drag reordering plus swipe actions. Add true layer duplication (new layer/stroke IDs, preserved style/pressure, one undo, document-limit guards). Left rail and Layers popover remain independently collapsible. No canvas coordinate shift when an overlay opens. Thumb generation uses existing scratch only, bounded80×48 images for at most32 rows, refresh after commits/board changes and never in penmove; cap nominal decoded thumbnail pixels at512KiB and preserve the five canvas/80MiB allocation invariant. This is a proposed engineering contract that needs independent readiness, not proven performance.

U2: keep the12 original presets and pressure/grain contract; use the workbook's category/sample library and hue-ring/inner-disc primary picker. Pencil pressure must affect darkness/coverage as well as width: apply a bounded coverage factor0.2+0.8*reportedPressure to the preset coverage when pressure is available, otherwise factor1. Tilt shading is a distinct device-capability addition and remains unverified, not faked with mouse pressure. Concepts shade palettes remain a secondary option so the primary visual target is unambiguous. Default HSV disc position persists hue at zero saturation; RGB/HSL fields and previews round-trip within one RGB unit. Original SVG/CSS assets only; do not commit the reference PDF, screenshots or copied artwork into the MIT app. UI settings remain bounded device-local state.

U3: add finger-hold eyedropper recognition650ms,8CSSpx navigation threshold, cancel on pointercancel/unexpected capture loss/blur/tool change, and no commit until release. Existing double/single chord recognizer modes remain; default is unresolved pending the one question. Hold assistance and vector transform remain in this checkpoint. Transparent-background support, rapid held Undo/Redo, canvas twist/fit gesture and three-finger destructive scrub are NOT silently bundled: each needs separate domain/recovery contracts and independent scope approval. They are reference parity gaps, not delivered functionality. Procreate's finger painting does not override the separately approved pen-first/no-finger-ink rule unless the user changes it.

Smudge stays a named dependency for the next painting-engine checkpoint after this batch; accepting the UI reference does not falsely close it. Until functional, no active Smudge button may claim success; keep its intended slot in the design with a clearly disclosed not-yet-available state if shown. Before any build, independent Gatekeeper must reconcile these additions to U1/U2/U3 budgets, model/paper schema, gesture/thumbnail performance and QA handoffs. The user should not approve ordinary technical choices. Do not restart discovery of already confirmed needs.
