# Procreate handbook: brush and adjustment engine review

Reviewed 2026-10-06. Planning only; no application code, tests, workflows or deployed behavior changed. Source: the current official handbook articles retrieved into the temporary reference corpus. All 19 Brushes and Adjustments pages were read, including the complete Brush Studio Settings article. The referenced handbook mixes 5.4 additions with older behavior; compatibility should be pinned by behavior, not presumed from a brand name.

The short **Reference behavior** entries below are original paraphrases, each below 80 words per source page. **UNRULY engineering implications** are our proposed implementation/acceptance analysis, not claims that Procreate supplies an algorithm, implementation specification, license, or portable engine.

## Baseline verified in UNRULY

`prototypes/browser-workspace/model.js` accepts four stroke types (`ink`, `pencil`, `marker`, `airbrush`), position and optional pressure. It has no persisted tilt, azimuth, preset, raster pixels, brush assets or adjustment graph. Layers have opacity but no blend-mode field. The runtime uses retained vector replay and a bounded five-surface renderer. P01 has an 80 MiB nominal backing-store budget; adding arbitrary permanent per-layer canvases would violate that architecture. Current brushes are an initial visual approximation, not Procreate brush-engine parity.

## Original engine dependency decisions

### Realistic pencil and inking presets: ready for bounded U2 design

Create HB/2B/6B as meaningful recipe differences in grain coverage, pressure-to-size/opacity response and edge character. A hard graphite pencil should not merely share the same particle brush with a different display name. Create distinct technical/fineliner/brush-pen behavior. Brush preview must use the same recipe code as the actual stroke. Save a recipe version or immutable evaluated parameters on each stroke, so changing the selected preset later cannot repaint historical marks unexpectedly. Imported legacy strokes retain their old appearance.

Position smoothing, pressure smoothing, taper and shape recognition are separate stages. Keep raw input capability data available to derive reproducible strokes; document whether saved points are raw or stabilized. Bound live buffering and avoid delayed endpoint jumps. A visible stabilization slider and an off state are more honest than promising Procreate's proprietary smoothing algorithm. The handbook explains perceived behavior, not exact filter coefficients.

Pressure is currently captured; tilt/azimuth are not in the saved point contract. Surface/Xiaomi browser input must be tested on the actual hardware before promising tilt-responsive shading. The app should degrade to an explicit pressure-only preset when tilt is missing. Apple Pencil Pro roll/squeeze-specific features are not portable requirements for these devices.

### Texture brush assets: separate bounded contract

Use an original tip mask plus optional repeatable grain image and original recipe fields. Persist IDs, hashes, dimensions, recipe version and RNG seed. Enforce decoded-pixel, asset-byte, stamp-count and import-count limits. Handle image decode failures, oversized files, unsupported media and quota errors atomically. A brush asset disappearing must not make an old board silently render differently; either embed required assets in document export or supply a manifest with a precise missing-asset error. Texture assets must be supplied with permission for redistribution; the MIT application license does not automatically cover third-party brushes.

### Smudge, gap-aware fill, clipping and Gaussian blur: raster foundation required

Do not pretend geometric vector erasing, lowering opacity, or painting a translucent line is pigment smudging. Introduce explicit layer content type and finite raster extent/tiles. Raster history needs reversible bounded tile patches or equivalent durable operations, not unbounded whole-canvas snapshots. Existing editable vector paths should remain editable on vector layers. Converting a vector layer to pixels must be explicit and reversible within the agreed history budget.

Gap-aware fill is a separate topology operation: colour tolerance and closing small boundary gaps are independent controls. Procreate fill thresholds elsewhere in the handbook must not be assumed to provide Clip Studio's requested gap-closing behavior. Define the analysed source (current/reference/visible layers), document-space gap distance, region bounds, anti-alias treatment, transparency and cancel behavior. Never close an arbitrary opening by silently filling the entire infinite board.

Clipping needs explicit parent/child relationships, alpha semantics, reordering constraints and serialization. A blend mode alone is not a clipping mask. Nested groups, clipping chains and viewport cache invalidation need separate tests before introducing them. Gaussian blur must preserve data beyond the screen and account for filter halos between raster tiles.

### Colour management and display limits

Brush colour selection, changing existing image colour and document colour profiles are different features. The current browser app has no documented ICC conversion pipeline. Keep initial numerical/export semantics explicit, and research browser/export colour handling before claiming CMYK, Display P3 or print accuracy. A Procreate-like disc does not create a colour-managed print workflow.

## Engineering acceptance common to future checkpoints

- A completed mark/effect is one reversible operation; preview changes cannot overwrite persisted originals before commit.
- All four existing brush types and legacy imported boards preserve appearance unless an explicit migration contract authorizes a change.
- Cache/reference outputs must agree for combinations of layer order, opacity, blend, selection and live stroke.
- Canvas memory bounds cover transient allocations, imported assets and filter scratch space, not just steady-state canvas dimensions.
- Expensive processing runs outside the live pen hot path; interruption, no-op, rejection and quota recovery are visible and do not lose saved work.
- Automated visual/functional tests establish behavior; Surface/Xiaomi tests establish pressure/tilt and handwriting feel. Neither replaces the other.

## Scope conclusion

Proceed with the revised U1 controls/layers, U2 original presets/colour UI, and U3 gestures/held shapes/selection-transform batch. Research has clarified dependencies; it has not made the raster engine, all Brush Studio settings or every advanced adjustment implementation-ready. Place smudge, textures, raster fill, clipping and Gaussian blur in explicit follow-on contracts, keeping them on the first-release roadmap where already requested. No empty control should imply that these engines already exist.
