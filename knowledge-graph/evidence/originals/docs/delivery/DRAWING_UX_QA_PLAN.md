## Readiness recommendation

**Conditionally ready as a bounded plan; not authorized or ready to implement yet.** U1 → U2 → U3 is a defensible sequence, with independent proof at each source snapshot and one combined preview/human review. The canonical proposal resolves the major risks through v3 isolation, an explicit blend/preset whitelist, bounded recognition, geometry-only transforms, and preservation of P01. Human ownership of the proposed UX lock and explicit build authorization remain outstanding; QA does not grant either.

Before executable assertions are frozen, settle these small but material contract details:

1. Define the 350 ms double-chord interval anchors. Proposed interpretation: first chord's final contact release to second chord's first contact down. Specify whether centroid uses start positions or another fixed definition, and whether chord duration starts at first down. Do not infer an easier timing rule during a failing test.
2. Specify startup when only `unruly-foundation` exists and no v2 workspace exists. Existing migration writes into v2, so it cannot be reused unchanged under the read-only v2/foundation rule. Recommend bounded read-only direct copying into v3 with explicit precedence if the same board ID exists in both sources. Existing legacy migration acceptance must survive.
3. Define safe behavior for rail/layer collapse or popover/layout changes during a live pen, hold-recognition, reorder, or pending transform. Such changes can move/resize the canvas while coordinates are frozen. Recommend deferring structural layout changes until contact ends, while pending transform keeps Apply/Cancel reachable. Specify the actual behavior before testing it.

The 56 CSS px layer row is a normal-text target, not a reason to clip large text or shrink primary controls below 44 CSS px; the proposal already allows rows to grow. Device preference settings must be validated and bounded, and must remain separate from artwork history.

## Independent fixtures and oracles

**Layers/blends:** deterministic three-layer red/green/blue crossing marks over white and warm patterned paper; opacity 0/.5/1; unique IDs and names, active layer at bottom/middle/top. Add a 32-layer list for limits/scroll/reorder. Independent blend oracle uses controlled source/destination pixels and native Canvas2D compositing, constructed independently of production replay helpers; include flat-colour exact expectations. Cached/full outputs remain byte-identical with zero tolerance. Native sRGB browser semantics are the contract; do not substitute claims about other apps' colour profiles.

**Legacy/presets:** retain the frozen original renderer fixture and P01 legacy four-brush/paper/pressure/opacity/view matrix. New v3 boards with absent preset and Normal layers must have exact old pixels at equal backing dimensions. All twelve presets use fixed geometry, seed and document coordinates; frames, samples, copies, eraser fragments and transforms must retain preset identity and grain determinism. No undocumented random seed or time-dependent sparkling.

**Gestures:** deterministic timestamped contact traces for chord count, staggered arrival/release, double/single mode, threshold boundaries, pan/pinch, touch during pen, cancellation and pending transform. Coordinates are CSS pixels across DPR 1/2/3 and view scales .1/1/8. Fake time belongs only in pure recognizer tests; actual Chromium pointer journeys use recorded event timing and bounded waits, with diagnostics when scheduling makes a boundary case unsuitable for browser timing assertions.

**Shape thresholds:** line endpoint distance at least 20 CSS px, path/chord ratio at most 1.2, maximum perpendicular deviation at most max(3 CSS px, 3% chord). Circle needs at least 12 samples, closure at most 20% diameter, radial RMS at most 12% radius, maximum radial error at most 25% radius, and at least 300 degrees coverage. Test every limit just inside and outside, plus exact boundaries in the pure recognizer. Hold timer is 650 ms since movement beyond 3 CSS px; raw restoration requires movement beyond 8 CSS px. These are prototype assumptions, not established device ergonomics.

**Shapes:** exact line, noisy qualifying line, near-threshold failing line, clockwise/counterclockwise sampled circle, 300-degree boundary, open arc, ellipse, tiny loop, repeated point, reversal and scribble. Independently calculate distance/deviation/closure/radial errors and affine expected geometry. Hold waits are time-controlled in pure tests; browser happy-path and cancel-after-hold journeys prove integration. Fit resampling remains capped at 1024 points. Pressure fixture includes null, zero and varying real reported values.

**Transforms:** fixed selection with two crossing strokes and one dot, plus outside stroke and another layer. Independently compute geometry around opposite corner/centre; exact style/ID/pressure preservation, with a documented numerical epsilon only for floating-point affine coordinates. This epsilon does not relax RGBA legacy/cache comparisons. Test 120 selected strokes/2400 points and document limits for bounded preview work.

**Storage:** source records in foundation/v2/v3 with distinct titles, last-board selection, revision metadata and current/previous pairs. Include duplicate source IDs, valid current, corrupt current/valid previous, both corrupt, mixed valid/invalid source boards, quota failure mid-copy, restart, 100-board cap, concurrent tabs and old-app edits after copy. Before/after deep byte snapshots prove source namespaces were not written or deleted. Copy occurs exactly once, retries failed copies, preserves identity and selected board where valid, and never labels a failed write Saved. Hostile imports include unknown/category-incompatible preset, unsupported blend, nonfinite/out-of-range values, duplicate IDs, oversize and HTML-like names. Data is validated atomically and never executed.

## Execution and evidence strategy after authorization

U1 requires pure ordering/schema/history cases, blend pixels, migration/storage integration, layout/reorder pointer journeys and the full P01 gates. U2 adds preset serialization/renderer determinism, legacy pixel proof, colour/control/UI-setting journeys and repeats impacted U1 plus P01 core. U3 adds pure gesture/shape/affine boundary cases, actual pointer/keyboard integration and **the complete combined inherited and DUX1 regression** against one immutable final source.

Use existing Node/Playwright tooling and deterministic fixtures; no new runtime package, paid call or backend. Browser profiles: desktop 1440×950, tablet portrait 768×1024 and landscape 1280×800, phone 360×800; DPR 1/2/3 allocation coverage and 200% text/keyboard-focus checks. Mouse and Chromium synthetic pen/touch verify browser contracts only. Record actual Chrome Ctrl+T behavior separately from a synthetic page keydown; inability to override browser-owned shortcuts is not hidden by synthetic success.

Each checkpoint binds source SHA, source/test/fixture hashes, contract IDs, fixture seed/version, commands, Node/browser versions, raw results and benchmark/allocation data. Capture failure screenshot/trace, console errors and external runtime requests. Retain every failure, classify product/test/environment defects, and return source repairs to the builder. Budget is at most two source repair batches and three CI runs per checkpoint; stop/replan if exhausted. Do not rerun passed suites broadly without a changed source, failure or unresolved risk.

Final QA may report PASSED only after actual combined execution on the exact reviewed source and no unresolved material defects. Gatekeeper consumes that evidence for the bounded preview decision. Main/production authorization, merged regression and physical Windows/Android pen feel remain separate. A single combined human card should cover independent panels/layers, HB/2B/preset differences, colour, DOUBLE history gestures, held shapes and lasso/transform; automation must not certify those physical or usability judgments.
