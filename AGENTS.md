# UNRULY repository continuation rules
Applies to this repository. User decisions in the current session take precedence.

## Required startup reads
Read docs/delivery/PRODUCT_ROADMAP.md, docs/delivery/CURRENT_CHECKPOINT.md, docs/delivery/CONTINUATION_CONTRACT.md and docs/delivery/CODE_STRUCTURE.md from current main. Verify actual source/head and read only the relevant implementation/test neighborhood. Historical PROJECT_STATE/review files preserve requirements; early native status is superseded by browser main. Never reconstruct total scope from the latest short chat summary.

## Preserve roadmap and report evidence
Update PRODUCT_ROADMAP.md after EVERY build/attempt, including failed, blocked, verified-unpublished and published outcomes. Record stable requirement/checkpoint identity, exact source/CI/deployment evidence where applicable, remaining acceptance gaps and next action. A completed subfeature does not close its whole original checkpoint. Keep all other pending rows.
Never remove, cancel or defer a user requirement through omission. Scope removal/deferral requires an explicit user decision/source. Distinguish a near-term subset count from total product work.
Maintain CURRENT_CHECKPOINT and CONTINUATION_CONTRACT consistently. All stale headings/status counts must be clearly historical or superseded.
Update CODE_STRUCTURE.md when affected module responsibilities/dependencies/contracts change; do not claim an AST/runtime map from a logical diagram.

## Bounded change discipline
Use unique scoped CHG branches/records. Before edits pin base and requirement, inspect affected callers, commit impact/plan with allowed and prohibited files plus linked regression obligations.
Compare actual diff with allowed scope; explain/revise every extra path before proceeding. Current path lists are NOT automatically enforced by the existing cumulative workflow. Do not claim protected approval/independent review from same-session tests.
Preserve cumulative behavior and regression assertions. Verify exact candidate source and hosted bytes before reporting publication. No unrequested broad architecture rewrite.
User has authorized verified personal-project main/Pages publication; preserve the current authorization and existing cumulative URL.

## Graph and skills
Routine roadmap/code-map/status updates are documentation, not knowledge graph regeneration. Do not modify .knowledge or knowledge-graph without explicit user permission. No skill modifications without a user request.
